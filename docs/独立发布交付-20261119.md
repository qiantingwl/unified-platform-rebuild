## 注册和独立运行

本程序的 `app` 负责前端、管理 API、分组选择、账户租约和转发，并运行自己的代理内核；`tasks` 使用同一个 PostgreSQL 领取注册及维护任务并写回执。需要浏览器的流程经内网调用专用 `browser`，该容器不持有数据库访问权限或数据库加密密钥。转发不需要任务服务在线；使用本程序代理内核的任务需要代理监听可用。实际模型平台、配置的短信渠道和网络出口仍是相关流程的正常外部条件。

调度对照 Agent2API 的组内候选、亲和与重试边界，任务对照已有签到、余额和回执流程；实现落在本程序原子租约、凭据版本和任务表。对照方在 Agent2API beta.3 上二开，使用 AG 转发与 3067 维护；两套产品各自发布，不共享数据库、任务入口或运行 API。

## 占位、换号、空返与缓存

- 占位继续由原开关控制，独立记时。上游角色帧、空白帧、用量帧不算有效首字；正文、推理或工具一旦开始，当前请求不再换号重放。首个有效输出前，明确可重试的错误在同一启动预算里换号；只有结束帧的空流、断流及 HTTP 200 流内错误均不能记成成功。错误与结束标记同帧时先处理错误。
- 增补两层用量修复：WPS 同一次尝试里的分帧用量按字段合并，缺失不覆盖、显式 0 保留；换号前失败尝试尚未输出正文时，它的用量及缓存不会发给客户端或写成成功尝试的统计。零 token 不用于判断有无正文。
- 对照 MiraiHub v1.1.4，新增 `UserUnauthorized` 明确业务码归为凭证失败。它走既有凭证复核与安全换号；普通 403 仍不自动认成凭证过期。官方缓存 session/run 在创建后非滑动复用一小时，只针对明确会话失效信号做重建。候选没有把泛化的上游拒绝转成会话重建，也没修改会话亲和、缓存键或消息上下文。
- 运行镜像另有同一 WPS 账户、同一会话亲和、约 2.4k 输入 token 公共前缀的两条样本：第一条有正文，输入 2,398、缓存明确为 0、总耗时 5.458 秒；第二条 1.662 秒 `upstream_rejected`，无正文或用量。不能证明缓存命中，也不能据此判定 run 已失效。运行镜像没有包含本轮新增的用量修补。
- 与独立核验对话互相核对了上述机制。对方在自己的 WPS 插件中亦确认并修复了分帧用量覆盖；两边均没有可确认的结构化 stale-run 业务码或真实同会话命中证据。此处只互换证据和做法，本程序运行不调用 3067 或对方程序。
